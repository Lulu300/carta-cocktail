## Summary

v1.18.0 adds link previews: a menu or cocktail link shared in a messaging app shows its title, description and photo. Settings gain a "Sign out everywhere" button. Fonts are now served by the app instead of Google Fonts. Stock warnings in the admin follow the interface language. No migration, no required action. Behind an HTTPS reverse proxy, the new optional `PUBLIC_BASE_URL` variable gives previews the right address.

## Changes

### Sharing

- **Link previews.** A link to a public menu (`/menu/<slug>`) or to one of its cocktails, shared in WhatsApp, iMessage, Slack, Telegram, Discord and other apps, now shows a preview with the title, the description and a photo. For a menu, the photo is that of the first visible cocktail that has one. Only public data is used: an unpublished menu or a hidden cocktail gives no preview. Visitors still get the usual page. (#266)
- **`PUBLIC_BASE_URL`.** This new optional variable sets the public address used in the previews, such as `https://carte.example.com`. Set it in `.env` when the site runs behind an HTTPS reverse proxy: without it, the address comes from the request, which nginx sees as `http`. The backend refuses to start with a value that is not an `http` or `https` address. See "Required actions" for older compose files. (#266)

### Admin

- **Sign out everywhere.** Settings have a "Sign out everywhere" button. After a confirmation, it ends the sessions of every device, this one included, and the sign-in page says so. (#258)
- **Stock warnings.** Warnings on cocktails, such as "only 2 servings left" or missing ingredients, now follow the interface language and show translated names. Before, they were in English. (#261)

### Public menu

- **Fonts.** Inter and Playfair Display are now served by the app instead of Google Fonts: the menu looks the same and the browser no longer contacts Google. The security policy (CSP) no longer allows the Google domains. (#260)
- **Page titles.** Browser tabs show the page, such as "Mojito · <site name>" or "Summer menu · <site name>", instead of the site name only. Admin pages are unchanged. (#260)
- **Loading.** The page shows the 🍸 icon and a dark background while it loads, instead of a white flash, and a message when JavaScript is disabled. (#260)

### Backups

- **Version in backups.** A backup exported by a published image now records the version of that image (`appVersion` in `metadata.json`), instead of `1.0.0`. Backups without it still restore. (#259)

### API

For clients that call the API directly:

- `GET /api/availability/cocktails` no longer returns `missingIngredients` and `lowStockWarnings` (the missing ones are the ingredients with `isAvailable: false`), nor `reason` on each ingredient. It adds `lowStock` (a list of `{ name, nameTranslations, servings }`), and `nameTranslations` and `orphan` on each ingredient. A line whose source is gone has `orphan: true` and an empty `name` (it was "Unknown"). The app does not use the removed fields anymore. (#261)

### Releases

- A release now runs the compose smoke test on the tagged commit before any image is pushed. (#264)

## Required actions

None. Pin both images to `:1.18.0`, or `:1.18` to follow the 1.18.x patch releases (`:1.17` does not move to 1.18.0), then pull and restart. There is no migration.

Instances older than v1.12.0: v1.12.0 is a breaking release. Apply its section of [`UPGRADING.md`](https://github.com/Lulu300/carta-cocktail/blob/main/UPGRADING.md#v1120) (and the sections before it) first, check that it works, then apply this one.

**Testing a pre-release**: use `:1.18.0-rc.N` instead of `:1.18.0`.

**Behind an HTTPS reverse proxy** (optional): set `PUBLIC_BASE_URL=https://<your domain>` in `.env`, so that link previews use the right address. The `docker-compose.prod.yml` of v1.17.0 and older does not pass it. Either download the new file, or add `- PUBLIC_BASE_URL=${PUBLIC_BASE_URL:-}` at the end of the `environment` list of `carta-cocktail-backend`. If you put lines back in a new file by hand, keep them at the end of that list.

**Rolling back** to v1.17.x: pin the images back to `:1.17`. There is no migration, so the database needs no restore.
