## Summary

v1.19.0 makes the public menu installable and readable offline, and stores new cocktail photos as optimized WebP copies. Pages load lighter photos. Unknown addresses now show a "Page not found" page. Admin error screens, warnings, plural messages and number formats are cleaner. No migration, no required action.

## Changes

### Public menu

- **Offline and installable.** Once a guest has visited the public menu and a cocktail page, they reload without network, with their photos, and the menu can be added to the home screen. This works over HTTPS only, or on `localhost`. Menu data is always fetched fresh first. The cached copy is used only when the network does not answer within 3 seconds. Admin pages and admin data are never cached. (#286)
- **Updates.** After an upgrade of the instance, the public menu reloads by itself on the new version. An open admin or sign-in page shows a banner, "A new version is available", with a "Reload" button. Nothing typed in a form is lost. (#286)
- **Photos.** Pages now load a copy of each photo sized for the screen: 480, 960 or 1600 px, lazy-loaded. (#287)
- **Page not found.** An unknown address, such as a mistyped link or an old QR code, now shows a "Page not found" page with a link to the home page. Before, it silently sent the visitor to the home page. (#272)
- **Unit converter.** Quantities follow the number format of the language, for example "3,33 cs" in French. (#278)
- **Recipe export.** A recipe export that fails now shows an error message, in the admin list and on the public page. An empty tag ("rum, ,mint") no longer shows an empty badge. (#277)

### Photos

- **New photos.** A new photo is stored as WebP, at most 1600 px wide, without EXIF data or GPS position. The uploaded file itself is not kept, neither on the server nor in backups. Link previews use a JPEG copy, which messaging apps display. (#287)
- **Existing photos.** They do not change. At the first start, the backend adds their reduced copies in the background, about 350 KB per photo, without touching the originals. It does the same after restoring an older backup. (#287)
- **Refused files.** A file with an accepted extension that cannot be read, such as a truncated JPEG or a HEIC renamed `.jpg`, now gets a clear error (400) instead of being stored as it is. So does an image of more than 100 megapixels. (#287)
- **Size checks.** A cocktail photo over 5 MiB and a bottle import file over 10 MiB are refused as soon as they are chosen, before anything is sent. (#270)

### Admin

- **Error screen.** When an admin page fails, the error screen keeps the sidebar and links to the dashboard. It takes the focus, and screen readers announce its title without its buttons. (#281)
- **Wide tables.** The bottles page no longer scrolls sideways on a wide screen. The sidebar keeps its width, and a table that is too wide scrolls inside its own frame. (#273)
- **Plurals.** Import and selection messages agree in number ("1 bottle imported", "2 bottles imported"). (#271)
- **Warnings.** Import warnings and information messages on the sign-in page are announced by screen readers. (#279)

### Operations

- **Reverse proxies and CDNs.** They must not cache `/sw.js`. If an old service worker ever gets stuck in a browser, `docs/operations.md` gives the steps to remove it.
- **Backend image.** It now includes `sharp` for the photo copies, about 9 MB larger.
- **Development.** TypeScript 6.0. The code is formatted with Prettier, and CI checks the formatting. Lint and tests are stricter. None of this changes the app.

## Required actions

None. There is no migration. Pin both images to `:1.19.0`, or to `:1.19` to follow the 1.19.x patch releases, then pull and restart. `:1.18` does not move to 1.19.0.

Instances older than v1.12.0: v1.12.0 is a breaking release. Apply its section of [`UPGRADING.md`](https://github.com/Lulu300/carta-cocktail/blob/main/UPGRADING.md#v1120) (and the sections before it) first, check that it works, then apply this one.

**Testing a pre-release**: use `:1.19.0-rc.N` instead of `:1.19.0`.

**Behind a reverse proxy or a CDN that caches**: make sure `/sw.js` is not cached, otherwise browsers keep an old version of the public menu.

**Rolling back** to v1.18.x: pin the images back to `:1.18`. The database needs no restore. Photos uploaded since the upgrade stay WebP, which v1.18 displays. Browsers that visited v1.19 keep its service worker and may keep showing the v1.19 public menu: v1.18 answers `/sw.js` with its home page, which browsers refuse as a worker, so they never remove it by themselves. On those browsers, clear the site data (step 2 of "Désinscrire un service worker bloqué" in [`docs/operations.md`](https://github.com/Lulu300/carta-cocktail/blob/main/docs/operations.md#désinscrire-un-service-worker-bloqué)).
