## Summary

v1.21.0 opens Carta to scripts and AI agents. The admin gets an "API" page that documents every route, API tokens for scripts, and an MCP server that lets an AI agent (Claude Code, Claude Desktop, a Cloudflare agent…) read the menu and the stock, and change them with a read and write token. Code Mode, which runs the agent's code on the server in a sandbox, is available too, off by default. At the first start, the backend copies the database to `backups/pre-migrate-<date>.db`, then applies two migrations: an empty table of API tokens, and the Code Mode setting, off. No required action.

## Changes

### API documentation

- **API page.** Admin > "API" lists every route of the API, what it accepts and what it returns, with a button to try a request with the open session. The viewer is served by the instance itself: it loads nothing from another site. (#308)
- **OpenAPI documents.** `GET /api/openapi.json` describes the public routes (public menus and cocktails, sign-in, health), without signing in. `GET /api/openapi/full.json` describes every route, for the signed-in admin. Both are OpenAPI 3.1, generated from the routes themselves, and carry the version of the instance. (#308)

### API tokens

- **New setting.** Settings > "API tokens" creates named tokens for scripts and MCP clients, read-only or read and write, which expire after 30, 90 or 365 days. A token starts with `carta_`, is shown only once, and can be revoked on its own. At most 20 tokens are active at a time. Only a hash of each token is stored. (#307)
- **Using a token.** Send it as `Authorization: Bearer carta_…`. A read-only token can only read (403 on a write), and a revoked or expired token gets 401. Tokens count in the API rate limit. `docs/operations.md` ("Jetons d'API") shows how to call the API with `curl`. (#307)
- **Reserved to the session.** No token can manage tokens, change the account, sign out everywhere, export or restore a backup, or turn Code Mode on (403). (#307, #310)
- **"Sign out everywhere"** now also deletes every API token, and its confirmation says so. (#307)
- **Backups.** Tokens are never part of a backup, and restoring a backup deletes them all: create the tokens of your scripts again after a restore. (#307)
- **Database.** One migration, `20261127180000_api_tokens`, adds an empty table. No existing value changes. (#307)

### MCP server for AI agents

- **New endpoint.** `/api/mcp` serves the Model Context Protocol (Streamable HTTP), with an API token. It goes through the same nginx proxy as the rest of `/api/`: nothing to configure. (#309)
- **Tools.** 12 tools read the cocktails, what the stock can make, the shortages, the bottles, categories, ingredients, units and menus. With a read and write token, 7 more adjust a bottle, create or update a cocktail, compose and publish a menu, and preview a cocktail import. No tool deletes anything, restores a backup or signs out everywhere. A read-only token does not see the write tools. **Prefer read-only tokens**: an agent has every right of its token. (#309)
- **Setup.** `docs/operations.md` ("Serveur MCP") has ready-to-paste setups for Claude Code, Claude Desktop (through `mcp-remote`) and a Cloudflare agent. The Cloudflare example follows their published code and documentation; it was not run against Cloudflare. (#309, #310)
- **Rate limit.** A tool call counts as two requests in `API_RATE_LIMIT`: the MCP request, and the tool's request to the API. (#309)

### Code Mode (off by default)

- **What it is.** Two more MCP tools, `search` and `execute`, in the form of Cloudflare's Code Mode. The agent writes a short JavaScript function: `search` runs it on the OpenAPI document, and `execute` lets it call the API with `codemode.request()`, with the rights of the token and the same limits as the tools. (#310)
- **Setting.** Settings > "MCP server: Code Mode" turns it on, after a confirmation, and off. Only the admin's session can change it. Off, `search` and `execute` are not listed and cannot be called. (#310)
- **Sandbox.** The agent's code runs in QuickJS compiled to WebAssembly, in a worker thread of its own, with no access to files, the network, `process` or the server's environment. Each run is limited to 10 s, 1 s of computation, 64 MB of memory for the code (96 MB at most for the whole WebAssembly sandbox) and 50 API calls, and its answer is cut at about 6,000 tokens. Two runs at most at a time, four more wait, and the next ones get 429. `codemode.request()` refuses deletions, the routes reserved to the session, and any path outside the API document, even with the session. (#310)
- **Backups.** Restoring a backup always turns Code Mode off, whatever the backup holds: turn it on again in Settings if you use it. (#310)
- **Database.** One migration, `20261127200000_site_code_mode`, adds the setting, off. No existing value changes. (#310)

## Required actions

None. `docker-compose.prod.yml` has not changed since v1.19.0. Pin both images to `:1.21.0`, or `:1.21` to follow the 1.21.x patch releases (`:1.20` does not move to 1.21.0), then pull and restart. At the first start, the backend copies the database to `backups/pre-migrate-<date>.db` and applies two migrations (see "API tokens" and "Code Mode").

Instances older than v1.12.0: v1.12.0 is a breaking release. Apply its section of [`UPGRADING.md`](https://github.com/Lulu300/carta-cocktail/blob/main/UPGRADING.md#v1120) (and the sections before it) first, check that it works, then apply this one.

**Testing a pre-release**: use `:1.21.0-rc.N` instead of `:1.21.0`.

**Rolling back** to v1.20.x: restore the `pre-migrate` copy made at the upgrade, then pin the images back to `:1.20`. Follow [`docs/operations.md`](https://github.com/Lulu300/carta-cocktail/blob/main/docs/operations.md#retour-arrière) ("Retour arrière") or [README › "Restoring a pre-migration backup"](https://github.com/Lulu300/carta-cocktail/blob/main/README.md#restoring-a-pre-migration-backup). What was entered since the upgrade is lost, API tokens included, and the copy brings back its sessions: set a new `JWT_SECRET` afterwards.
