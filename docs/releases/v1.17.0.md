## Summary

v1.17.0 adds an upgrade guide to the admin. After an upgrade, a banner lists the required actions of the versions you skipped. It shows from the next upgrade on: this version only records itself. The backend image is about 10 % lighter. Dependencies are up to date, among them React 19.3 and Express 5.3. At the first start, the backend copies the database to `backups/pre-migrate-<date>.db`, then applies one migration that adds an empty table. No required action.

## Changes

### Upgrade guide in the admin

- **Banner after an upgrade.** When the backend starts on a newer version than the one that ran before, the backend log and a banner on every admin page list the required actions of each version in between, oldest first, as written in the release notes. Actions to do *before* an upgrade are listed separately, to check afterwards: the new version cannot show them in time. The banner stays until you click "I have done these actions" ("J'ai fait ces actions"). [`UPGRADING.md`](https://github.com/Lulu300/carta-cocktail/blob/main/UPGRADING.md) stays the reference. (#255)
- **From the next upgrade on.** The version that ran before v1.17.0 is not known, so upgrading to v1.17.0 shows no banner: the backend only records its version. The banner first appears when you upgrade from v1.17.0 to a later version. A downgrade logs a warning and shows no banner. Restoring a backup does not bring back a false banner. (#255)
- **Database.** One migration, `20261126120000_app_state`, adds a one-row table for the version that last ran. At the first start, the backend copies the database to `backups/pre-migrate-<date>.db` (in the `db-data` volume) before applying it. No existing row changes. (#255)
- **API.** For clients that call the API directly: `GET /api/system/upgrade-notice` (204 when there is nothing to show) and `POST /api/system/upgrade-notice/acknowledge`, both for the signed-in admin. (#255)

### Menus

- **API.** For clients that call the API directly: `PUT /api/menus/:id` now answers 400 (`errors.cocktailNotAllowedInMenu`) when `cocktails` is not empty on an Aperitifs or Digestifs menu, system or personal. `cocktails: []` is still accepted. The admin never sends this. (#250)

### Docker

- **Lighter backend image.** About 15 MB less to download (148.6 to 133.9 MB compressed for amd64, 460 to 398 MiB on disk). Files that are never loaded at run time are left out, and `src/` is no longer in the image. Migrations at the first start, backups, restores, photo uploads and `check-integrity` work as before. (#252, #253)
- **Building the backend image yourself.** The image now holds the release notes, which the upgrade guide reads. They come from a named build context.
  - A custom compose file that builds the backend image must add `additional_contexts: { releases: ./docs/releases }` under `build:` (Docker Compose 2.17 or later).
  - A manual `docker build` needs `--build-context releases=./docs/releases`.
  - The published images and the repository's `docker-compose.yml` need nothing. (#255)
- **npm install scripts.** The install scripts the build needs are now allowed explicitly (`allowScripts`), so the images keep building with npm 12. (#254)

### Dependencies

- Backend: Express 5.3, zod 4.6, express-rate-limit 8.7 and other minor updates. (#241)
- Frontend: React 19.3, React Router 7.18, TanStack Query 5.108, react-hook-form 7.92, `@hookform/resolvers` 7, Vite 8.3 and other minor updates. The admin forms show the same validation messages. (#243, #247)
- Test tooling only: jsdom 31, msw 3, `@testing-library/jest-dom` 8. (#244, #245, #246)

## Required actions

None. `docker-compose.prod.yml` has not changed since v1.16.0. Pin both images to `:1.17.0`, or `:1.17` to follow the 1.17.x patch releases (`:1.16` does not move to 1.17.0), then pull and restart. At the first start, the backend copies the database to `backups/pre-migrate-<date>.db` and applies one migration (see "Upgrade guide in the admin").

Instances older than v1.12.0: v1.12.0 is a breaking release. Apply its section of [`UPGRADING.md`](https://github.com/Lulu300/carta-cocktail/blob/main/UPGRADING.md#v1120) (and the sections before it) first, check that it works, then apply this one.

**Testing a pre-release**: use `:1.17.0-rc.N` instead of `:1.17.0`.

**If you build the backend image yourself** (custom compose file or `docker build`), add the `releases` build context (see "Docker"). Otherwise the build fails.

**Rolling back** to v1.16.x: restore the `pre-migrate` copy made at the upgrade, then pin the images back to `:1.16`. Follow [`docs/operations.md`](https://github.com/Lulu300/carta-cocktail/blob/main/docs/operations.md#retour-arrière) ("Retour arrière") or [README › "Restoring a pre-migration backup"](https://github.com/Lulu300/carta-cocktail/blob/main/README.md#restoring-a-pre-migration-backup). What was entered since the upgrade is lost, and the copy brings back its sessions: set a new `JWT_SECRET` afterwards.
