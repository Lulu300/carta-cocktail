## Summary

v1.15.0 makes the type of a bottle category a real link in the database: at the first start, the backend copies the database to `backups/pre-migrate-<date>.db`, then applies one migration. No category is refused, changed or lost. The backup screen now refuses an archive larger than 200 MB as soon as it is chosen, before anything is sent. i18next moves to version 27, which closes a moderate advisory that did not affect Carta. A new operations guide, [`docs/operations.md`](https://github.com/Lulu300/carta-cocktail/blob/main/docs/operations.md) (in French), covers installation, backups, upgrades and rollback. No required action.

## Changes

### Database

- **Category types.** The type of a category (Spirit, Syrup, Soft or a custom type) is now a foreign key to the list of category types, so a category can no longer point to a type missing from that list. A new type entered in a category, or brought by a bottle or cocktail import, is still added to the list. Deleting a type that categories still use is refused with the same message as before. (#202)
- **Migration at the first start.** The backend copies the database to `backups/pre-migrate-<date>.db`, next to the database (`/app/data/backups/` in the `db-data` volume), then applies the migration `20261124120000_category_type_relation`. The migration copies every category as it is. (#202)
- **Types created by the migration.** A type used by a category but missing from the list of types is created first, in gray and without translations. The backend already created these types at every start, so on an instance in service the migration normally creates none. Names are kept exactly as written: `syrup` next to `SYRUP` gets a type of its own. Such a type shows in the "Category Types" window, opened by "Manage Types" on the Categories page, where you can give it a color and translations. (#202)
- **If the migration fails**, the backend does not start, and its log names the `pre-migrate` copy to restore. Restore that copy as in [README › "Recovering from a failed migration"](https://github.com/Lulu300/carta-cocktail/blob/main/README.md#recovering-from-a-failed-migration): do not run the migration again without restoring it. (#202)
- **Integrity check.** Run on a database that has not been migrated yet, `check-integrity` may still list "Category types missing from CategoryType (created by the migration)". There is nothing to fix: the migration creates them, and this line does not change the exit code (0). (#202)
- **API.** For clients that call the API directly: `categoryType` is no longer `null` in `GET /api/categories`, `GET /api/categories/:id` and `GET /api/shortages`. The shape of the answers does not change. (#202)

### Backup and restore

- **Archives larger than 200 MB.** Settings > Backup & Restore refuses an archive larger than 200 MB (209,715,200 bytes) as soon as it is chosen, under the file picker, with "The file or request is too large" ("Le fichier ou la requête est trop volumineux" in French). Nothing is sent, and the "Restore Backup" button does not show. Before, the whole archive was sent and then refused; above about 210 MB, nginx refused it during the upload, which Firefox did not read: it sent the archive again ten times, then said that the restore might still be running, although nothing had reached the backend. (#201)
- **Restoring a backup made before v1.15.0.** Its database has the old schema, so the restore screen asks to restart the backend, as for the earlier migrations. The migration runs at that restart, after the `pre-migrate` copy. See [UPGRADING.md › "Restoring a backup from an older version"](https://github.com/Lulu300/carta-cocktail/blob/main/UPGRADING.md#restoring-a-backup-from-an-older-version). (#202)

### Translations

- **i18next 27.** The backend and the frontend move to i18next 27, the frontend to react-i18next 18. The app shows the same texts. (#203)
- **Upper-case language codes.** For clients that call the API directly: `Accept-Language: FR` or `?lng=FR` now gets the error messages in French. Before, they came in English, with French number formats. The app sends `fr`, `en` or `en-GB` and is not affected. (#203)

### Documentation

- **Operations guide.** [`docs/operations.md`](https://github.com/Lulu300/carta-cocktail/blob/main/docs/operations.md), in French, gives the commands for installation, health checks, cold backups and restores of the volumes, the export by cron, upgrades, rollback, the admin password reset, the rotation of `JWT_SECRET` and HTTPS behind a reverse proxy. The production section of the README now starts with pinning `:<major>.<minor>` and links to it. The startup warning about the old default admin password now names Settings > Admin Profile. (#204)

### Security

- **i18next.** i18next 27 closes GHSA-6jcc-5g8w-32mx (moderate), in `addResourceBundle` with deep merge. Carta only calls it with the translation files shipped in the image, so it was not exploitable. (#203)

## Required actions

None. `docker-compose.prod.yml` has not changed since v1.12.0: pin both images to `:1.15.0` (or `:1.15` to follow the 1.15.x patch releases; `:1.14` does not move to 1.15.0), then pull and restart. At the first start, the backend copies the database to `backups/pre-migrate-<date>.db` and applies one migration (see "Database").

Instances older than v1.12.0: v1.12.0 is a breaking release. Apply its section of [`UPGRADING.md`](https://github.com/Lulu300/carta-cocktail/blob/main/UPGRADING.md#v1120) (and the sections before it) first, check that it works, then apply this one.

**Testing a pre-release**: use `:1.15.0-rc.N` instead of `:1.15.0`.

**Rolling back** to v1.14.x: restore the `pre-migrate` copy made at the upgrade, then pin the images back to `:1.14`, as in [`docs/operations.md`](https://github.com/Lulu300/carta-cocktail/blob/main/docs/operations.md#retour-arrière) ("Retour arrière") or [README › "Restoring a pre-migration backup"](https://github.com/Lulu300/carta-cocktail/blob/main/README.md#restoring-a-pre-migration-backup). What was entered since the upgrade is lost. The copy brings back its sessions: set a new `JWT_SECRET` afterwards.

**If you download `docker-compose.prod.yml` again** (not needed for this release), put back the lines you added to the `environment` list of `carta-cocktail-backend`: the file does not have them. In particular `- SQLITE_WAL=false` (database on a network share, see [README › "Database files and network shares"](https://github.com/Lulu300/carta-cocktail/blob/main/README.md#database-files-and-network-shares)), after `- UPLOAD_DIR=/app/uploads`, otherwise the database goes back to WAL mode, which does not work on SMB or NFS. The same goes for `API_RATE_LIMIT`, `LOGIN_RATE_LIMIT`, `TRUST_PROXY` and the other variables you added there.
