## Summary

v1.9.0 reworks the public menu for guests on their phones: loading placeholders, clear error messages with a retry button, back from a cocktail without reloading the menu, and a section bar on long menus. The backend now checks every request against a strict format, and warns at startup when the photo folder is not a mount. The admin shows the version it runs. No required action; one optional check after the upgrade.

## Changes

### Public menu

- **Loading and errors.** The public pages show placeholders while loading instead of a "Loading…" text. A network or server error shows "Unable to load" with a **Retry** button, and is no longer shown as "No menus" on the home page. An unknown menu or cocktail shows "not found" with a link back. A search with no result says so and offers to clear the search; screen readers hear the number of results. (#68)
- **Back without reload.** The back link of a cocktail page is a real link (right-click and new tab work). Coming from the menu, it goes back in the history: the menu is not downloaded again and opens at the same scroll position. A guest keeps a menu in memory for 5 minutes: a guest who browses an open menu sees an admin change after 5 minutes at most, or at once after reloading the page. A signed-in admin always gets fresh data. (#68)
- **Section bar.** A menu with at least 2 sections (or 2 categories on a bottle menu) gets a bar of section chips under the header. A tap scrolls to the section and the bar follows the scroll. The search field and the bar stay at the top of the screen. (#68)
- **Admin order on bottle menus.** Bottles, and the category blocks of a bottle menu without sections, follow the order set in the admin instead of being sorted by name. (#68)
- **Search.** The bottle search ignores accents, like the cocktail search ("apero" finds "Apéro"). (#68)
- **Layout.** The "Login" link moves from the header to a discreet footer with the site name. A cocktail card shows at most 4 ingredient pills, then "+N". On the recipe page, Export and Print become secondary buttons under the recipe. The bottle locations window closes with Escape. "% vol.", "ml" and the bottle and cocktail counts are translated, with plurals. (#68)
- Cocktails are still greyed out only when their availability switch is off; greying out by stock comes in a later version.

### Admin

- **Version shown.** The bottom of the admin sidebar shows the version of the running frontend (`v1.9.0`), or `dev` for a local build. (#67)

### Backend

- **Request validation.** Every request is checked before it reaches the database. An invalid request answers `400` "Validation error" with the list of the wrong fields (`details`); the admin forms only show the generic message until a later version. Requests accepted before and refused now: (#69)
  - **Cocktail form:** an ingredient line with a quantity of `0` (typed, or the field cleared), and a line whose bottle, category or ingredient is left on "--". **A cocktail already saved with a quantity-0 line** can no longer be saved from the form (even for a rename) until that line is fixed: see "After upgrading".
  - **Bottle import with a hand-made file:** a file with one out-of-range row (empty or `0` capacity, a percentage above 100, a negative price or desired stock, an unreadable opening date, a translation in a language other than fr/en) passes the preview, but its confirmation is refused as a whole and nothing is imported. Fix the row and import again. Files exported by the app pass, as long as the stored values respect the bounds below.
  - **Out-of-range values:** remaining percentage outside 0-100 or not an integer, alcohol percentage outside 0-100, negative purchase price, capacity of 0 or less, negative desired stock, minimum percentage outside 0-100, negative unit conversion factor, negative menu or section position, batch quantity above 50 (it used to be capped at 50).
  - **Other API calls:** wrong types (for example a number as the site name), non-numeric ids, `?categoryId=x` on the bottle list and export, an export format other than json/csv, a repeated `?force`, an unknown or incoherent `sourceType` on a recipe line, preferred bottles on a line that is not a category, an empty recipe step, a blank name on an update (it used to be ignored), an unknown menu type, translations in a language other than fr/en.
- **Values kept.** A desired stock of `0` is saved as `0` (it was turned into `1` on creation), and a purchase price or alcohol percentage of `0` is saved as `0` (it was erased). (#69)
- **Cocktail import.** Only the expected fields of the units, categories, bottles and ingredients created by an import are saved: an `id`, a date or a purchase price slipped into the file is ignored. A name left blank in the import wizard takes the name from the file; a unit with no name in the file is named after its abbreviation. (#69)
- **Photo folder check at startup.** In a container, the backend warns in its logs when its photo folder (`/app/uploads`) is not a mounted volume or host folder, since photos stored there are lost when the container is recreated. It also logs how many cocktail photos are missing from that folder. Both warnings link to `UPGRADING.md`; the first one says to copy the photos out of the container before recreating it. The logs only hold counts and the folder path, and the check never stops the backend. (#66)

### Development

- The frontend CI fails when the JavaScript loaded by the public menu grows above 140 kB gzip or includes admin pages or jszip. (#65, #68)

## Required actions

None before upgrading. `docker-compose.prod.yml` has not changed since v1.8.0: pin both images to `:1.9.0`, then pull and restart.

Instances older than v1.8.0: apply the section of every version in between first, following [`UPGRADING.md`](https://github.com/Lulu300/carta-cocktail/blob/main/UPGRADING.md), check that it works, then apply this one.

**Testing a pre-release**: use `:1.9.0-rc.N` instead of `:1.9.0`.

### After upgrading

1. **Optional, no data loss.** If saving a cocktail from the admin form fails with "Validation error", one of its ingredient lines probably has a quantity of `0` (the form used to save `0` when the field was cleared). Set a positive quantity on that line, or remove it, then save again. Until then, the cocktail is still displayed and served as before.

If the backend logs a `[uploads] WARNING` at startup, follow the guide it links to.
