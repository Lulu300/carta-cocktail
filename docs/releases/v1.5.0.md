## Summary

v1.5.0 fixes data loss (cocktail photos, menu sections), closes security holes (public JWT secret, default admin password, private data on the public API) and fixes several admin bugs. **It is a breaking release:** the backend no longer starts without a strong `JWT_SECRET`, and existing photos must be copied out of the old container before the upgrade. Follow the required actions below, in order.

We recommend pinning the images to `:1.5.0` instead of `:latest`: the next 1.x releases also contain breaking changes, each with its own required actions.

## Changes

### Data loss fixes

- **Cocktail photos are now stored in the `uploads` volume.** Until now the backend wrote them to `/uploads`, inside the container, instead of the volume mounted on `/app/uploads`: every container recreation, so every update, deleted them. The image now sets `UPLOAD_DIR=/app/uploads` (new setting, also set in both compose files). (#28)
- **Menu sections are kept when a cocktail menu is saved.** Saving the cocktail menu editor used to move every cocktail back to "Without a section". Assignments lost before this fix cannot be recovered. (#27)
- Saving a menu is atomic: on error, nothing is changed. Unknown menu: 404 instead of 500. A section that belongs to another menu is refused (400). (#27)
- A partial update of a cocktail (`PUT /api/cocktails/:id` with only some fields, for example `{ "isAvailable": false }`) no longer deletes its ingredients, instructions and tags. The update is atomic: an unknown unit or bottle returns 400 and leaves the recipe as it was. Unknown cocktail: 404. (#34)

### Security

- **`JWT_SECRET` is required.** The backend refuses to start when it is missing, shorter than 32 characters, or one of the values published in this repository (`default-secret`, `change-me-to-a-random-secret`, `your-random-secret`, `test-secret`). Both compose files refuse to start without it. A new secret logs out current sessions; data is not affected. (#36)
- **The admin account is no longer rewritten at each start.** Before, the seed reset the admin email and password from `ADMIN_EMAIL` / `ADMIN_PASSWORD` (default `admin123`) at every container start, so a password changed in the settings came back at the next restart. Now:
  - on a new database, the admin is created from `ADMIN_EMAIL` (default `admin@carta.local`) and `ADMIN_PASSWORD`, which is required: at least 12 characters, not `admin123`. Without it, the backend stops at the seed with a clear error;
  - an existing admin is left as is. `ADMIN_EMAIL` and `ADMIN_PASSWORD` are ignored once the admin exists;
  - `ADMIN_RESET_PASSWORD=true` (exactly `true`) resets the admin email and password from the environment at startup. `false` and an empty value are ignored silently; any other value is ignored with a warning in the log;
  - while the admin password is still `admin123`, the backend logs a warning at each start. (#36)
- **Public API hardening** (`/api/public/*`). (#33)
  - The admin preview of unpublished menus requires a valid token. An invalid, forged or expired token is treated as a guest, and an unpublished menu returns 404.
  - Hidden cocktails and bottles are removed from public menus on the server, for everyone.
  - Public responses no longer contain inventory fields (purchase price, opening date, remaining level, aperitif and digestif flags). The bottle location is still shown on bottle menus.
  - **A cocktail that is not visible in any published menu returns 404 to guests**, including through a direct link or the export link. Links already shared to such cocktails stop working. The logged-in admin can still open any cocktail.
  - Cocktail notes and preferred bottles are returned only to the admin. The public recipe search no longer matches words found only in notes.
  - A non-numeric cocktail id returns 404 instead of 500.
  - The item counts on the public menu list leave out hidden items and empty bottles.
  - Tokens are verified with the HS256 algorithm only.
- Dependency security updates: `i18next-http-middleware` (critical advisory), `multer`, `morgan`, `react-router-dom` and Express transitive dependencies, plus minor updates of React, Vite, Tailwind CSS, i18next and Prisma 6.19.3. (#30)

### Admin

- **Wrong current password in Settings > Admin Profile:** the API returns **400** with "Current password is incorrect" instead of 401, and the admin is no longer logged out. (#35)
- An expired session redirects to the login page, then back to the page that was open. Error messages from the server are shown in the interface language. (#35)
- Cocktails: "Select all" only selects the cocktails shown by the current search, and keeps the ones selected by hand. A double click on Save creates a single cocktail. Save errors are shown on the page. If the photo upload fails after a new cocktail is created, the next save updates it instead of creating a duplicate. (#32)
- Shortages: loading and error states, with a retry button. (#32)
- Bottles: "Save and duplicate" refuses an empty name. "Add" is disabled while no category exists. (#32)
- The slug and type of the system menus (Aperitifs, Digestifs) can no longer be changed: the API returns 403. Their name, description and visibility can still be changed. (#27)

### Public menu

- The browser language is detected correctly: a `fr-FR` browser gets French names for categories, ingredients and units, and the language selector shows the right language. Unsupported languages fall back to English. The page `lang` attribute follows the selected language. (#29)

### Docker and nginx

- The frontend accepts requests up to 20 MB (nginx default was 1 MB), and up to 512 MB for a backup restore. (#31)
- gzip compression for HTML, CSS, JavaScript, JSON, CSV and SVG, including API responses. (#31)
- Cache headers: hashed assets cached for one year, `index.html` and app pages always revalidated, photos cached for 30 days. (#31)
- New compose variables: `UPLOAD_DIR` (backend, `/app/uploads`) and `ADMIN_RESET_PASSWORD` (default `false`). `JWT_SECRET` has no default, `ADMIN_PASSWORD` no longer defaults to `admin123`. (#28, #36)

## Required actions

The commands assume the default `docker-compose.prod.yml`, run from its folder. Adapt the file name and the service name `carta-cocktail-backend` if yours differ.

Recommended first: export a backup from Settings > Backup & Restore. A backup made with the old version contains the database and the photos.

### Before upgrading

1. **Copy the existing photos out of the running backend container.** The old version stores them in `/uploads`, inside the container: pulling the new image and recreating the container deletes them. Do it while the old container is still running:

   ```bash
   BACKEND=$(docker compose -f docker-compose.prod.yml ps -q carta-cocktail-backend)
   docker exec "$BACKEND" ls -la /uploads        # the photos to rescue
   docker cp "$BACKEND":/uploads/. ./uploads-rescue/
   ```

   If `/uploads` does not exist, no photo was uploaded since the container was last created: there is nothing to rescue. Photos uploaded before the last container recreation are already lost; restore them from a backup if you have one.

2. **Set `JWT_SECRET` in the `.env` file next to the compose file.** It must be at least 32 characters long and must not be one of the values published in this repository (see "Security" above). If your `.env` already has a random `JWT_SECRET` of 32 characters or more, keep it.

   ```bash
   JWT_SECRET=<output of: openssl rand -hex 32>
   ```

   For a **new database** only (first start, empty `db-data` volume), also set `ADMIN_PASSWORD` (at least 12 characters, not `admin123`) and, optionally, `ADMIN_EMAIL` (default `admin@carta.local`). On an existing database the admin is kept as is and these two variables are ignored.

3. **Update `docker-compose.prod.yml` to the v1.5.0 version**, keeping your own changes (ports, for example). The new file refuses to start without `JWT_SECRET`, no longer sets `ADMIN_PASSWORD` to `admin123`, and passes `ADMIN_RESET_PASSWORD` to the backend (needed in step 2 of "After upgrading"). Then **pin both images to `:1.5.0`**:

   ```bash
   cp docker-compose.prod.yml docker-compose.prod.yml.bak
   curl -fsSLo docker-compose.prod.yml https://raw.githubusercontent.com/Lulu300/carta-cocktail/v1.5.0/docker-compose.prod.yml
   ```

   ```yaml
   image: ghcr.io/lulu300/carta-cocktail/backend:1.5.0
   image: ghcr.io/lulu300/carta-cocktail/frontend:1.5.0
   ```

   Testing a pre-release (`v1.5.0-rc.N`): the `v1.5.0` compose URL and the `:1.5.0` images only exist after the final release. Use `v1.5.0-rc.N` in the `curl` URL and pin the images to `:1.5.0-rc.N` instead.

Then upgrade:

```bash
docker compose -f docker-compose.prod.yml pull
docker compose -f docker-compose.prod.yml up -d
```

### After upgrading

1. **Copy the rescued photos into the uploads volume.** The container was recreated, so read its id again:

   ```bash
   BACKEND=$(docker compose -f docker-compose.prod.yml ps -q carta-cocktail-backend)
   docker cp ./uploads-rescue/. "$BACKEND":/app/uploads/
   docker exec "$BACKEND" ls -la /app/uploads
   ```

   No restart is needed. Check that the photos show on a cocktail page, then delete `./uploads-rescue/`. The photos now survive container recreations.

2. **Change the admin password if it is still `admin123`.** The old version reset the password to `ADMIN_PASSWORD` at every start, or to `admin123` when `ADMIN_PASSWORD` was not set, even after a change in the settings. If you never set `ADMIN_PASSWORD`, your password is `admin123`, and the backend log says so at each start. Log in (the new `JWT_SECRET` ended the previous sessions), then either:
   - change it in Settings > Admin Profile; it now survives restarts and updates; or
   - set `ADMIN_RESET_PASSWORD=true` and a new `ADMIN_PASSWORD` (at least 12 characters) in `.env`, run `docker compose -f docker-compose.prod.yml up -d`, check the log line `Admin credentials reset from environment (login email: …)`, then remove `ADMIN_RESET_PASSWORD` from `.env` and run `up -d` again. Otherwise every restart resets the password.

3. **Assign the cocktails to their sections again.** Saving a cocktail menu with an older version moved every cocktail back to "Without a section", and these assignments cannot be recovered. In Admin > Menus, open each cocktail menu that uses sections and assign its cocktails again. From this version on, sections are kept.
