## Summary

v1.14.0 moves the frontend image to the official nginx image, on nginx 1.31.x (the mainline branch), with the nginx security fixes of 2026-11-18 and 2026-11-23 and updated Alpine packages. When the server refuses a form, the admin's error message now names the field to fix ("Name: required") instead of "Validation error". The bottle editor of a menu shows translated category names, and the API sends translated names as objects on every route, which changes the answer of a few routes for scripts that call the API directly. No required action: the frontend still listens on port 8080 only, `docker-compose.prod.yml` and the database do not change.

## Changes

### Frontend image

- **Official nginx image.** The frontend image is now built on `nginx:1.31-alpine` instead of `nginxinc/nginx-unprivileged:1.30-alpine`, which had not been rebuilt since 2026-10-19 and still shipped nginx 1.30.6. It runs nginx the same way as before: as uid 101, on port 8080, with the same headers, healthcheck and `BACKEND_HOST`. It still starts under another uid of group 0 (`user: "12345:0"`). The image follows the 1.31.x patch releases when it is rebuilt: the published v1.14.0 ships nginx 1.31.10 or a later 1.31.x. (#194)
- **Port 8080 only, as before.** The official nginx image declares port 80. The frontend image is rebuilt on an empty base so that it declares port 8080 only, like the v1.13.x image. Reverse proxies need no change, including those that pick the container port by themselves (Traefik without `loadbalancer.server.port`, nginx-proxy without `VIRTUAL_PORT`, SWAG's auto-proxy mod without `swag_port`). (#194, #198)
- **What the image no longer carries.** The variables of the official nginx image (`NGINX_VERSION`, `PKG_RELEASE`, `DYNPKG_RELEASE`, `NJS_VERSION`, `NJS_RELEASE`, `ACME_VERSION`) and its `maintainer` label are gone from `docker inspect`; nothing in the image read them. `docker compose -f docker-compose.prod.yml exec carta-cocktail-frontend nginx -v` gives the nginx version. Scanners that read the installed Alpine packages see the same packages; a tool that recognises the base image from the image history no longer sees `nginx`. (#198)
- **acme module.** The nginx 1.31 packages add the `ngx_http_acme_module` module to the image. Carta does not load it. (#194)

### Error messages

- **The field to fix.** When the server refuses what the admin entered, the error notification now names the field and the rule, and the row for a list: "Name: required" or "Row 2, Quantity: value too small" ("Nom : obligatoire", "Ligne 2, Quantité : valeur trop petite" in French), instead of "Validation error". It shows the first field it can name; once that one is fixed, saving again shows the next one, if any. This applies to every admin notification and to the error screen of the bottle import, where a row of the import's categories reads "Category 2, Name: required". A case still reachable today is a name made only of spaces: the browser accepts it and the server refuses it. A field or rule the app cannot name keeps the server's message. (#195)

### Translations

- **Category names in the bottle editor of a menu.** The bottle editor of a menu, and its panel of bottles removed from a system menu (Apéritifs, Digestifs), now show the category names in the admin's language. They showed the base name before. (#193)
- **Empty translations.** A language left blank in a translated name is no longer stored, and a name with no translation left is stored without translations. Before, an empty object was stored as `{}`. The forms already sent only the languages the admin filled in, so this mostly concerns scripts and imports. (#193)
- **Unreadable translations in the log.** A stored translation that is not valid JSON is still sent as `null` ("no translation"). One that is valid JSON but not an object (such as `"Rum"` or `[]`), which used to be sent as is, is now sent as `null` too. In both cases the backend log now says `Ignoring unreadable nameTranslations: <value>`. It writes this line each time it reads the row, so on every request that returns it, until the name is saved again from the admin. (#193)
- **API.** For clients that call the API directly; the app needs nothing. These answers now send `nameTranslations` as a JSON object instead of a JSON string, like the other routes (#193):
  - `GET /api/public/units`;
  - `GET /api/menus/:id`, for the categories, ingredients and units nested in its cocktails and bottles, and `PUT /api/menus/:id`, for the categories of its bottles;
  - `GET /api/menu-bottles/menu/:menuId`, `POST /api/menu-bottles`, `PUT /api/menu-bottles/:id` and `GET /api/menu-bottles/menu/:menuId/exclusions`;
  - the `existingMatch` of each reference in `POST /api/cocktails/import/preview`.

### Site settings

- **First load.** On a database without site settings yet (the seed creates them), two requests for the settings at the same time could make one of them fail with a `409` error. The settings row is now created once, whatever the number of requests. (#193)

### Security

- **nginx.** nginx 1.31.x brings the nginx security fixes of 2026-11-18 and 2026-11-23. Nine of the ten CVEs fixed on 2026-11-18 affected nginx 1.30.6, and so did CVE-2026-132779 of 2026-11-23. Only one of them reaches Carta's configuration: CVE-2026-123634 (severity medium for nginx), a use-after-free in the resolver, which nginx uses to find the backend on each request. The others need HTTP/2, HTTP/3, TLS, the mail or stream modules, or `alias` with `try_files`, which the frontend image does not use: its nginx serves plain HTTP/1.1. (#194)
- **Alpine packages.** The frontend image moves from Alpine 3.24.2 to 3.24.4, with fixes in musl, zlib, expat, brotli, libxml2, libxslt, curl and openssl. (#194)
- **Backend dependency.** The Prisma configuration loader of the backend image (`@prisma/config`) now uses `effect` 3.22.5 instead of 3.20.0 (GHSA-7589-6fvf-x4pw). The copy bundled inside the Prisma CLI stays 3.20.0 until a fixed Prisma release. No untrusted input reached the affected code. (#192)

## Required actions

None. The frontend image still declares port 8080 only, so no reverse proxy needs a change. `docker-compose.prod.yml` has not changed since v1.12.0: pin both images to `:1.14.0` (or `:1.14` to follow the 1.14.x patch releases; `:1.13` does not move to 1.14.0), then pull and restart. No migration: the backend makes no `pre-migrate` copy and the database does not change.

Instances older than v1.12.0: v1.12.0 is a breaking release. Apply its section of [`UPGRADING.md`](https://github.com/Lulu300/carta-cocktail/blob/main/UPGRADING.md#v1120) (and the sections before it) first, check that it works, then apply this one.

**Testing a pre-release**: use `:1.14.0-rc.N` instead of `:1.14.0`.

**If you download `docker-compose.prod.yml` again** (not needed for this release), put back the lines you added to the `environment` list of `carta-cocktail-backend`: the file does not have them. In particular `- SQLITE_WAL=false` (database on a network share, see [README › "Database files and network shares"](https://github.com/Lulu300/carta-cocktail/blob/main/README.md#database-files-and-network-shares)), after `- UPLOAD_DIR=/app/uploads`, otherwise the database goes back to WAL mode, which does not work on SMB or NFS. The same goes for `API_RATE_LIMIT`, `LOGIN_RATE_LIMIT`, `TRUST_PROXY` and the other variables you added there.
