## Contexte

La carte est consultée sur téléphone par des invités, parfois avec un lecteur d'écran ou un zoom fort. L'admin se pilote mal au clavier : aucun indicateur de focus, des champs sans nom accessible, des menus déroulants qui ne se ferment pas avec Échap. Cette tâche passe après les refontes de pages (E-05, E-06, E-07) pour ne corriger chaque fichier qu'une fois, et fait le tour de ce qui reste.

## Problème constaté

Comptages sur le code actuel (hors tests) :

- **Focus** : `focus:outline-none` ×79, `focus-visible` ×0. Les boutons du `LanguageSelector` (`LanguageSelector.tsx:66-70`) et du `MultiSelectDropdown` (`MultiSelectDropdown.tsx:36-40`) n'ont aucun style de focus de remplacement.
- **Labels** : 64 `<label>`, 0 `htmlFor`, 91 champs (`input` ×71, `select` ×15, `textarea` ×5). Exemple : `pages/auth/LoginPage.tsx:51, 63`. Champs de recherche sans `aria-label` : `MenuPublicPage.tsx:240`, `SearchInput.tsx:22-28` ; bouton d'effacement de `SearchInput.tsx:30-38` sans nom.
- **Modales** : 12 overlays sans `role="dialog"`, sans Échap (`grep Escape` : 0), sans gestion du focus. E-03 fournit `Modal` ; E-05 à E-08 et E-11 l'adoptent.
- **Listes déroulantes** :
  - `MultiSelectDropdown.tsx:36-50` : pas d'`aria-expanded`, `aria-haspopup`, `aria-controls`, pas d'Échap ; bouton « retirer » sans nom (`:60`).
  - `LanguageSelector.tsx:69` : `aria-label="Change language"` en anglais en dur, pas d'`aria-expanded` ni d'Échap.
  - `LocationAutocomplete.tsx`, `CategoryFilterInput.tsx` : pas de rôle `combobox`, pas de navigation aux flèches ; boutons d'effacement sans nom (`LocationAutocomplete.tsx:35`, `CategoryFilterInput.tsx:54`). Les options sont des `<button>` atteignables par Tab : la revue exagère en disant « souris seulement ».
  - `IconPicker.tsx:60-74` : 50 emojis avec `title` seul, sans `aria-pressed` ; textes français en dur (`:55, 84, 93, 101, 108`).
- **Mise en page** : pas de lien d'évitement ; `AdminLayout.tsx:94-101` bouton hamburger sans nom ni `aria-expanded` ; barre latérale mobile fermée (`:42-45`) translatée hors écran mais toujours atteignable au clavier ; overlay (`:83-88`) sans Échap ; emojis de navigation (`:9-19`) lus par les lecteurs d'écran.
- **Pagination** (`Pagination.tsx:42-88`) : boutons `««`, `«`, `»`, `»»` sans nom, page courante sans `aria-current`, pas de `<nav>`.
- **Contraste** : `text-gray-500` ×70 (environ 3,6:1 sur `#1a1a2e`, sous le seuil AA de 4,5:1), `text-gray-600` ×8 (environ 2,4:1, ex. `Pagination.tsx:59`, `UnitsPage.tsx:99`).
- **Cibles tactiles** : boutons ✕ et pagination en `px-2 py-1`, environ 20-28 px.
- **Mouvement** : `transition-all` ×7, `group-hover:scale-105` (`PublicCocktailItem.tsx:47`), aucun `motion-reduce:`.
- **Annonces** : aucun `aria-live` pour le nombre de résultats, les chargements ou les erreurs (les toasts d'E-04 couvrent les mutations).
- `<html lang>` figé : traité par A-08, ne pas refaire ici.

## Ce qu'il faut faire

1. **Focus global** dans `index.css` :
   ```css
   :focus-visible { outline: 2px solid var(--color-accent); outline-offset: 2px; }
   ```
   Supprimer tous les `focus:outline-none` restants, ou les remplacer par `focus-visible:` quand un style propre est voulu. Le `focus:border-amber-400` des champs peut rester en complément.
2. **Labels** : passer les champs restants sur `Field` / `Input` d'E-03. Reste à faire après E-05 à E-07 : `LoginPage`, `SettingsPage`, `SearchInput` (prop `label` obligatoire, rendue en `sr-only`), recherche de `MenuPublicPage`. Les champs de recherche prennent `type="search"` et `enterKeyHint="search"`.
3. **Listes déroulantes** :
   - `MultiSelectDropdown` et `LanguageSelector` : `aria-expanded`, `aria-haspopup="listbox"` (ou `menu`), `aria-controls`, Échap ferme et rend le focus au bouton, `aria-label` traduit. Options de langue en `role="menuitemradio"` avec `aria-checked`.
   - `LocationAutocomplete` et `CategoryFilterInput` : motif combobox de l'APG (`role="combobox"`, `aria-expanded`, `aria-controls`, `aria-activedescendant`, flèches haut/bas, Entrée, Échap). Écrire un hook partagé `components/ui/useComboboxKeyboard.ts` plutôt qu'une dépendance (Headless UI ajouterait environ 25 kB).
   - `IconPicker` : `aria-label` traduit par emoji (nom générique « Emoji 🍋 » si pas de nom), `aria-pressed` sur la sélection, textes passés en i18n.
4. **Mise en page** : lien « Aller au contenu » dans les deux layouts ; `AdminLayout` : `aria-label` et `aria-expanded` sur le hamburger, `inert` sur la barre latérale fermée en mobile, Échap ferme, `NavLink` avec `aria-current="page"`, emojis `aria-hidden`. `PublicLayout` : `<nav>` autour des liens d'en-tête.
5. **Pagination** : `<nav aria-label={t('pagination.label')}>`, `aria-label` sur les 4 boutons, `aria-current="page"`, cibles d'au moins 40×40 px.
6. **Contraste** : remplacer `text-gray-500` par `text-fg-muted` (gray-400) pour tout texte porteur d'information ; garder gray-500 seulement pour du décoratif. Supprimer `text-gray-600` sur fond sombre.
7. **Mouvement** : `motion-reduce:transition-none motion-reduce:transform-none` sur les transitions et agrandissements.
8. **Annonces** : région `aria-live="polite"` pour le nombre de résultats dans les listes filtrées admin. Pour la carte publique, voir E-11.
9. **Couleurs restantes** : passer aux tokens d'E-03 les fichiers qu'aucune autre tâche n'a migrés (`LoginPage`, `SettingsPage`, `DashboardPage`, `ShortagesPage`, layouts, composants `ui/` existants).
10. Ajouter `vitest-axe` en dépendance de dev et un helper `src/test/axe.ts`.
